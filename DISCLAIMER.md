## 2. What the tool actually does

Every claim below is verifiable in `php2shell_audit.py`:

| It does | It does **not** do |
|---------|--------------------|
| Runs `php -v` / `php --ini` / reads `php.ini` and process lists | Modify, install, or configure anything on the audited host |
| Sends **one** `HEAD` request per remote target | Send exploit traffic, multipart bodies, or oversized payloads |
| Falls back to **one** `GET` only if the server rejects `HEAD` (403/405/501) | Retry, fuzz, brute-force, or probe for crash behaviour |
| Reads `Server:`, `X-Powered-By:`, `Set-Cookie` response headers | Attempt to trigger OOM, use-after-free, or any memory corruption |
| Writes a report only when you pass `--json PATH` | Phone home, collect telemetry, or upload results anywhere |

**There is no exploit code in this repository, and none is generated by it.**
The tool cannot confirm exploitability, cannot execute code on a target, and does
not attempt to.

本仓库**不包含任何 Exploit 代码**，工具也不会生成 Exploit。该工具无法确认漏洞可利用性，不会在目标上执行代码，也不会尝试这么做。

## 3. `UNKNOWN` does not mean safe

This is the single most important limitation.

`UNKNOWN` is not `PASS`. It means **the tool could not determine the answer**.

Remote mode can only report what a server volunteers. A server that hides its
version, sits behind a CDN or reverse proxy, returns a stripped header set, or
blocks the scan will be reported as `UNKNOWN` **even when it is fully vulnerable**.
PHP can be present and vulnerable with no version string in any header at all.

Conversely, `VULNERABLE` is not proof of exploitability — it means a disclosed
version is below a fixed release. Exploitation depends on configuration, build
options, reachable code paths, and attack preconditions the tool cannot observe.

**Do not treat a clean run as evidence of security. It is not a penetration test.**

`UNKNOWN` 不等于 `PASS`。它的意思是**工具无法判定**。

远程模式只能读取服务器主动披露的信息。隐藏版本、位于 CDN 或反向代理之后、返回精简响应头、或阻断扫描的服务器，即使完全存在漏洞，也会被报告为 `UNKNOWN`。PHP 可能存在且易受攻击，而所有响应头中都不含版本号。

反之，`VULNERABLE` 也不代表可利用——它只说明披露的版本低于修复版本。实际可利用性取决于配置、编译选项、可达代码路径等工具无法观测的前提。

**不要把「扫描结果干净」当作安全证明。它不是渗透测试。**

## 4. Distro backports cause false positives

Distribution vendors frequently **backport** the security fix into an older
version number without bumping it. A Debian, Ubuntu, RHEL, or Alpine package may
report `8.4.16` while already containing the patch for these CVEs.

The tool compares version numbers, so it will label such a host **`VULNERABLE`**
even though it is patched. This is a known and expected false positive.

Before acting on a `VULNERABLE` result, confirm against your vendor's security
advisory and package changelog:

```bash
# Debian / Ubuntu
apt changelog php8.4 | head -40
# RHEL / Fedora
rpm -q --changelog php | head -40
# Alpine
apk info -a php84 | head -40
```

发行版厂商常将安全修复**回移至**旧版本号而不升级版本号。Debian、Ubuntu、RHEL、Alpine 的软件包可能报告 `8.4.16` 但已包含针对这些 CVE 的补丁。

本工具按版本号比较，因此会把这类主机标记为 **`VULNERABLE`**，尽管它已修复。这是已知且预期的误报。

## 5. Data accuracy and third-party sources

The fixed-version baseline (`8.2.35` / `8.3.36` / `8.4.27` / `8.5.12`), the CVE
identifiers, and the mitigation guidance are taken from public advisories. That
information is **third-party data**: it may be incomplete, may change after
publication, and may be superseded.

If upstream revises an advisory, this tool's output can become wrong without any
change to the tool. **Always confirm against the primary source before making a
decision:**

- <https://github.com/php/php-src/security/advisories/GHSA-w8hw-w9fx-j79w>
- <https://github.com/php/php-src/security/advisories/GHSA-6wmf-4rv5-p3rp>
- <https://www.cve.org/>

Mitigation directives change behaviour and require restarting workers. **Test
them in a staging environment first.** The `--local` audit reports whether a
directive is set as recommended; it does not evaluate whether doing so is
appropriate for your workload.

修复版本基线、CVE 编号与缓解建议均取自公开公告，属**第三方数据**：可能不完整、可能在发布后变更、也可能被后续公告取代。

若上游修订公告，即使本工具未改动，其输出也可能变为错误。**决策前务必核对一手来源。**

缓解措施会改变运行时行为且需重启 worker。**请先在测试环境验证。** `--local` 只报告指令是否按建议设置，不评估该设置是否适合你的业务负载。

## 7. Report handling

`--json` output may contain internal hostnames, IP addresses, software versions,
and configuration details of your infrastructure. Treat such reports as
**confidential**. Do not commit them to public repositories — `.gitignore` already
excludes `report*.json`, `out.json`, and `targets.txt` for this reason.

Do not paste reports into public issue trackers or LLM chats without redacting
hostnames and IPs.

`--json` 输出可能包含内网主机名、IP、软件版本与配置细节。请将这些报告视为**机密**，不要提交到公开仓库（`.gitignore` 已为此排除 `report*.json`、`out.json`、`targets.txt`）。

在未脱敏主机名与 IP 前，不要粘贴到公开 issue 或 AI 对话中。

## 8. Binary distributions

The Windows executable published as a Release asset is **unsigned**. Windows
SmartScreen will warn on first launch; macOS Gatekeeper may block it.

Verify the checksum against `SHA256SUMS.txt` from the same release before running:

```cmd
certutil -hashfile php2shell-audit.exe SHA256
```

A checksum confirms the download matches what was published. It does **not**
guarantee the build is free of defects — see section 1.

作为 Release 附件发布的 Windows 可执行文件**未签名**，首次运行会触发 SmartScreen 警告，macOS Gatekeeper 可能拦截。

运行前请对照同一 Release 中的 `SHA256SUMS.txt` 校验。校验和只能确认下载内容与发布内容一致，**不能保证构建无缺陷**——见第 1 节。
